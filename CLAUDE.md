# archipelagos — CLAUDE.md

## What this is

**archipelagos** (`archipelagosjournal.org`) is a peer-reviewed, born-digital academic journal devoted to Caribbean digital humanities. It publishes scholarly essays, digital project exchanges, and project reviews. The journal is trilingual: English, Spanish, and French. ISSN: 2689-842X.

This repository (`archie-next`) is a migration of the original Jekyll 4.x site to **Eleventy 3.x**. Issues 1–9 are integrated. The live domain `archipelagosjournal.org` still points to the old Jekyll site until final validation and cutover.

## Architecture

- **Static site generator:** Eleventy 3.x (Node.js), output to `_site/`
- **Templates:** Nunjucks (layouts in `src/_layouts/`, includes in `src/_includes/`)
- **Markdown:** markdown-it with footnotes, attrs, and smart quotes (`markdownTemplateEngine: false` — markdown is never pre-processed by Nunjucks)
- **Styles:** Plain CSS in `src/public/css/` — unchanged from the original Jekyll site
- **PDF pipeline:** Pandoc 3.x + lualatex, scripts in `utility/latex/`
- **i18n:** Custom — YAML files in `src/_i18n/{en,es,fr}.yml` for UI strings; the about/authors/credits/reviewers/valences/workflow info pages and the cfp/open + cfp/special call-for-papers pages live as native Eleventy pages (front matter + markdown body) in `src/_i18n/{en,es,fr}/`, with a per-language `{lang}.11tydata.js` directory data file supplying the shared `layout`/`lang` defaults. Any such page can be taken down without deleting it by adding `published: false` to its front matter — `{lang}.11tydata.js`'s `eleventyComputed.permalink` returns `false` (no output written) when that's set, otherwise falls through to the page's own static `permalink` unchanged. Used to close a call for papers between issues (`cfp/special.md`) without losing the content as a template for next time.

## Key conventions

**URL structure is frozen.** Article URLs must match the original Jekyll output exactly — DOI resolvers and citations depend on them. Permalinks use `.html` extensions (not directory indexes), e.g. `/issue01/haynes-mapping.html`.

**`date:` is reserved by Eleventy.** Human-readable publication dates live in `pubDate:` in front matter, not `date:`.

**Current issue** is always the last key in `src/_data/issues.js` — `site.js` derives it dynamically. No manual config change is needed when adding a new issue; just add it as the last entry. The homepage's featured issue, its TOC, and the issues list on every issue page (`src/_includes/issues-list.njk`, listing every issue with the current one highlighted the same way the active language is in the header) all follow this automatically too.

**`allIssueArticles` collection** is also derived dynamically from `Object.keys(issues)` in `.eleventy.js` — no changes needed there when adding a new issue.

**Language variants** are generated by `src/es/issue-articles.11ty.js` and `src/fr/issue-articles.11ty.js` — JS class templates that paginate over `collections.allIssueArticles` and emit pages at `/es/issueXX/slug.html` and `/fr/issueXX/slug.html`.

**Interactives are two files, not one.** A piece like Marisa Parham's `.break .dance` is JavaScript-rendered, so its HTML exposes ~47 characters of text where an article exposes ~89,000 — invisible to search engines, to the site's own search, and to a screen reader before the animation loads. So every interactive ships as a pair:

1. **A companion page** — markdown at `src/issueXX/<slug>.md` with `section: interactives` and full article front matter, whose body carries the piece's linear text and links onward into it. This is an ordinary article in every respect: `article.njk`, `head.njk`, the `/es/` and `/fr/` generators, search, sitemap, atom and every `check-issue` gate treat it like any other. **It is the citable object and carries the DOI.**
2. **The interactive itself** — flat HTML/JS under `src/issueXX/<name>/`, passed through untouched via `addPassthroughCopy` + `eleventyConfig.ignores` (derived automatically from the `url` field, `.eleventy.js:65-71`). It carries `<link rel="canonical">` pointing at its companion, and asserts **no** `citation_doi` — otherwise one DOI is claimed by two URLs and reads to Crossref and Google Scholar as duplicate records.

`src/_data/issues.js`'s `interactives` array is a **build manifest**, not a display source: `url` drives the passthrough loop and the raw page's sitemap entry, `companion` records the pairing. `toc.njk` renders the Featured section from articles with `section: interactives`, so those links localize like every other TOC entry.

`section: interactives` is a fifth value alongside `introduction | articles | projects | reviews`. Its labels already exist in all three `_i18n/*.yml` files (Featured / Destacado / En vedette) and in `search-script.njk`'s section map.

**Do not run `utility/intake/normalize-inline.pl` across a whole file.** It is built for Pandoc's markdown *body* output and escapes quotes as `\"` / `\'`; inside YAML front matter that produces `unknown escape sequence` and the build fails.

**Images are co-located per issue:** `src/issueXX/images/filename.jpg` → served at `/issueXX/images/filename.jpg`. Eleventy detects and copies each issue's images directory automatically (`.eleventy.js` loops over `issues.js` keys); the PDF pipeline (`convert.sh`) reads from the same path.

**i18n labels:** Every issue must have a label in all three yml files under `issues:` or the homepage will fall back to a blank entry. Example: `issue09: "Issue (9) | Theme | Month YYYY"`.

**Heading levels are load-bearing, not just visual.** `article.njk`/`project.njk` already emit the page's only `<h1>` (the title) — article body markdown must start its own sections at `##` (h2), never `#`. The abstract heading and the "Authors' Bios" heading are also h2, as siblings of the body's own `##` sections — never skip from h1 straight to h4 or lower. `check-a11y.js` (see Issue integrity check) enforces this automatically via axe-core's `heading-order` rule.

**Alt text must describe the image, not name the file or duplicate a generic label.** `alt="schoolclass"` (the filename) or reusing one image's alt text on a different image are both real bugs that have shipped before — `check-images.js` now flags filename-shaped alt text and duplicate alt text reused across images within the same article, in addition to the existing missing/empty-alt and minimum-width checks.

## Issue intake workflow

For forthcoming issues, use the scripts in `utility/intake/`:

```bash
# 1. Scaffold the folder
bash utility/intake/new-issue.sh issue09

# 2. Register in src/_data/issues.js and add labels to all three i18n yml files

# 3. Convert each Word file
bash utility/intake/convert-docx.sh src/issue09/incoming/author-title.docx

# 4. Edit the generated .md — fill in every # TODO field
#    section must be exactly: introduction | articles | projects | reviews | interactives
```

`convert-docx.sh` handles automatically:

- Images extracted to `src/issueXX/images/slug-imageN.ext` (no `media/` subdirectory)
- Image paths rewritten to absolute `/issueXX/images/…`
- Tables converted from Pandoc grid format to HTML (works in markdown-it; journal.lua reads them back as LaTeX tables for PDF)
- `{.mark}` highlighted spans stripped (Word copy-editing artifact → `\hl{}` LaTeX error)
- `{.underline}` spans stripped (Word auto-underlined hyperlinks → stray literal brackets in rendered HTML)
- `{dir="rtl"}` spans stripped from curly/smart quotes
- Bare curly/smart quotes (`‘ ’ “ ”`) normalized to the same escaped straight-quote form (`\"` / `\'`) Pandoc already uses everywhere else — most commonly needed inside table cells, where the nested `pandoc.write` call in `tables-to-html.lua` bypasses Pandoc's normal smart-quote-to-straight-quote conversion, so Word's autocorrected curly quotes pass through as literal Unicode characters instead of being caught like they are in regular paragraph text

**Inline normalization lives in `utility/intake/normalize-inline.pl`, and is Perl rather than `sed` on purpose.** BSD `sed` (macOS) matches *bytes*, not characters, unless the caller's locale is UTF-8. In the `C` locale a class like `[“”]` becomes the byte set `E2 80 9C 9D`, which also matches the first two bytes of every other `U+20xx` character — em dash, en dash, ellipsis, narrow no-break space — replacing them and orphaning the trailing byte, so the output stops being valid UTF-8. That made the script's correctness depend on the caller's environment: fine from an interactive Terminal with `LANG` set, silently corrupting from cron, CI, or a bare shell. `perl -CSD` decodes UTF-8 itself, so behavior is identical everywhere. For the same portability reason the script uses `perl -i` rather than `sed -i ''`, which is BSD-only syntax and fails on GNU sed. Run `bash utility/intake/test-normalize-inline.sh` to check it — every case runs under both a UTF-8 and a `C` locale, since that difference is the whole point.
- Figure rubric blocks converted to `<figure>` HTML (`utility/intake/convert-images.py`) — authors type a `caption=`/`alt=`/`url=` rubric as its own paragraphs (blank line between each, no manual line break inside one) immediately after the figure. Two shapes are recognized:

  1. **Embedded image** (preferred): the author inserts the real picture directly in the .docx (Insert > Picture) at the point it belongs; `pandoc --extract-media` already pulls it out and renames it before this script runs, so the author only needs to follow it with:

     ```
     caption="insert caption here"

     alt="insert alt text here."

     url="http://optional-url.com"
     ```

  2. **Placeholder** (image not embedded yet — an editor must separately drop a matching file into `images/`): same rubric, with an `img=` filename line first:

     ```
     img="my-image.jpg"

     caption="insert caption here"

     alt="insert alt text here."

     url="http://optional-url.com"
     ```

  `url` is optional in both shapes; the rest are required. Quotation marks inside `caption` or `alt` must be escaped with a backslash (`\"`). A block that doesn't match either shape exactly — wrong order, a missing required field, a field split across paragraphs, or an image that's inline within a sentence rather than alone on its own paragraph — is left as plain text/a bare image in the output markdown for manual conversion. Run `bash utility/intake/test-convert-images.sh` to check the converter against its fixtures.

## PDF pipeline

To generate a single article:

```bash
bash utility/latex/convert.sh src/issue09/article.md
```

To regenerate a full issue:

```bash
bash utility/latex/makeIssues.sh issue09
```

Requires Pandoc ≥ 3.0 and lualatex (TeX Live). The template uses TeX Gyre Heros (open-source Helvetica Neue equivalent).

**Known Lua filter behaviors in `journal.lua`:**

- `Pandoc` walker: reassembles HTML `<figure>` RawBlock sequences into `\includegraphics` LaTeX
- `Image`: strips `width` attribute; strips leading `/` from src so lualatex resolves relative to resource-path
- `RawBlock`: converts HTML `<table>` blocks (produced by intake) back to Pandoc Table elements for LaTeX
- `Span`: strips `{.mark}` highlighted spans
- `Underline`: strips `{.underline}` spans (Pandoc 3.x AST node) to prevent `\ul{}` errors
- `Meta`: flattens nested `title: {long: ..., short: ...}` for Pandoc metadata
- `Div`: converts `.epigraph` divs to `\epigraph{}{}`

## Link checking

```bash
npm run build && npm run check-links   # prints broken links to stdout
npm run report-links                    # writes broken-links.txt + missing-local.txt
```

`[0]` status on local image paths is a linkinator limitation, not a real error. The check also runs in CI on every push (`continue-on-error: true`).

**Same-page anchor links** (`href="#id"`) are checked separately, by `npm run check-anchors` (`utility/check-anchors.js`), also wired into CI (`continue-on-error: true`). linkinator's own `checkFragments` option was tried first but turned out to be unreliable in a recursive crawl: it only validates fragments on pages reached within the first hop or two of the crawl's entry point (e.g. a root-level page like `credits.html`, discoverable directly from the site root) and silently skips validation — no warning, no result, nothing — for pages reached deeper in the recursion, which is nearly all of this site's real content (`issueXX/*.html`, `es/`, `fr/`, footnote anchors). `check-anchors.js` instead does a plain per-file HTML scan (every `id="..."`/`name="..."` vs. every `href="#..."` in the same file, skipping the bare `href="#"` "return to top" idiom) — no crawling, no recursion-depth blind spot, so coverage doesn't depend on how deep a page sits in the site.

## Issue integrity check

Before cutting over a finished issue, run a full integrity gate over just that issue:

```bash
npm run check-issue -- issue09   # defaults to the current issue if omitted
```

Runs (`utility/check-issue/`): HTML validity (`html-validate`, config tuned to ignore this codebase's deliberate self-closing-void-tag/inline-table-style/legacy-DC-meta conventions — see `htmlvalidate.config.json`), link integrity (`check-issue-links.js`, linkinator's programmatic API, scoped to the issue's own built pages as crawl entry points but still following `recurse` into the rest of the site, serving from `_site/` — not the repo root — as the document root so root-relative links resolve the same way they do in production; unresolved links are treated as hard failures here, unlike `report-links.sh` — except on domains listed in `utility/check-issue/flaky-domains.json`, which are still requested and still listed in `log.md` under "Tolerated (flaky domains)" but don't gate publication; that list exists because web archives and DOI/handle resolvers rate-limit hard under a recursive crawl and otherwise bury the real failures. It is deliberately narrower than linkinator's own `skip` list, which suppresses the request entirely, and its `tolerateStatuses` excludes 404/410 so a missing snapshot or dead handle still fails), same-page anchor links (`check-anchors.js`, scoped to the issue's own built pages via the manifest — see Link checking above for why this is a separate check from `check-issue-links.js` rather than relying on linkinator's `checkFragments`), front-matter completeness (checks parsed field values against the intake stub's known placeholder text, not just a literal `# TODO:` grep — catches cases where the prefix was stripped but the placeholder text wasn't replaced) and i18n label presence in all three yml files, curly/smart quotation marks left over from Word (flags literal `‘ ’ “ ”` characters in the markdown source — `convert-docx.sh` now normalizes these at intake time, so this check is mainly a safety net for hand-edited content or articles converted before that fix), image existence + non-empty alt text + minimum width + alt text that looks like a raw filename + duplicate alt text reused across images in the same article (`utility/check-issue/check-issue.config.json`, default 800px, matching the author guidelines), PDF existence for every article that doesn't set `pdf: false`, footnote anchor pairing (every `#fnrefN` has a matching `#fnN` and vice versa), and an accessibility scan (`check-a11y.js`, axe-core run against jsdom — no headless browser dependency — checking heading order, landmarks, labels, and ARIA under the `wcag2a`/`wcag2aa`/`best-practice` rule sets, `color-contrast` disabled since jsdom can't compute real CSS cascade/layout).

`check-a11y.js` has one hardcoded, documented exception (`KNOWN_EXCEPTIONS` in the script): the `region` rule on `#sidebar-checkbox` and its `<label>`, which drive the site's CSS-only mobile-menu toggle via sibling selectors in `main.css` (`#sidebar-checkbox:checked + .sidebar`, `~ .wrap`, `~ .sidebar-toggle`) that require both elements to stay direct body-level siblings — wrapping them in a landmark would break the toggle. Every other rule and node still fails normally.

Every run writes `log.md` at the repo root (gitignored, overwritten each run — `utility/check-issue/generate-log.js`) with one section per check, for triaging failures without scrolling back through terminal output. Images and Links get extra structure since those are the two categories expected to need manual, per-item triage: the Images section is a table of file / image path / problem; the Links section splits Internal vs External and gives each broken/unresolved link's source file:line (resolved by matching the link's raw href/src text back against the issue's own markdown, falling back to site templates in `src/_includes`/`src/_layouts`, then to the built HTML page if neither contains it — e.g. for a link assembled from a template variable rather than typed literally) alongside the HTTP status or "unresolved" for a timeout/network error. Internal (`_site`-local) broken results are cross-checked directly against the filesystem before being reported, since local checks share a concurrency pool with slow external requests during a large recursive crawl and can otherwise time out spuriously even when the file exists.

`bash utility/check-issue/test-check-issue.sh` runs the fixture-based unit tests for the individual check scripts (`utility/check-issue/fixtures/fixture-root/`), following the same pattern as `utility/intake/test-convert-images.sh`.

Manual script only — not wired into CI.

## Accessibility

Site-wide landmark structure (`default.njk`): skip-to-content link → `<aside>` (sidebar) → `<header>` (masthead) → `<main id="main-content">` → `<footer>`. Footnote back-references get a localized `aria-label` via an Eleventy transform (`.eleventy.js`, `footnote-backref-label`) rather than at the markdown-it level, since Eleventy doesn't thread the page's `lang` into markdown-it's render `env`. The auto-generated table of contents (see below) gets its `<nav>` landmark labeled the same way (`toc-nav-label` transform) — any page with a TOC has two `<nav>` landmarks (sidebar + TOC), and both need distinct accessible names or `html-validate`'s `unique-landmark` rule fails.

**Table of contents:** any page can drop `[[toc]]` on its own line to get an auto-generated nested list of links to that page's own `##`/`###` headings — used on `about → src/_i18n/{en,es,fr}/authors.md`, `reviewers.md`, and `valences.md`. Powered by `markdown-it-anchor` (assigns heading ids) and `markdown-it-toc-done-right` (builds the link list), wired into the shared `md` instance in `.eleventy.js` with a shared custom `slugify` function — both plugins **must** use the same slugify, or the TOC's hrefs won't match the ids actually on the headings. The custom slugify strips accents and punctuation instead of falling back to each library's own percent-encoded default (`café` → `cafe`, not `caf%C3%A9`). Repeated heading text (e.g. `valences.md`'s four "Review Process" subsections) gets deduplicated independently by both plugins (`-1`, `-2`, ...) — this only stays in sync because both walk the same heading sequence with the same slugify function, so don't change one without the other. TOC only lists `##`/`###` (`level: [2, 3]` in the plugin config) — deeper headings (e.g. `authors.md`'s `####` Documents/Images/Video subsections) still get real ids from `markdown-it-anchor` for manual cross-reference links (`[Images](#images)`), just aren't listed in the TOC itself. This replaced dead Jekyll/kramdown syntax (`{:toc}`, `{:.no_toc}`) left over from the migration that rendered as literal garbage attributes under markdown-it.

**Color contrast:** `npm run check-contrast` (`utility/check-contrast.js`) checks a small hardcoded set of known text/background color pairs in `main.css` against their WCAG AA thresholds (4.5:1 normal text, 3:1 large text) — pure hex-math, no CSS parsing/rendering. It's an allowlist, not a general linter: extend `PAIRS` in that script whenever a new text color is added to `main.css`. Wired into CI (`.github/workflows/build.yml`) as a non-blocking step, same pattern as `check-links`.

Test with `bash utility/test-check-contrast.sh`.

## Deployment

Two targets, one workflow (`build.yml`). Push to `staging` → GitHub Pages preview at `elotroalex.github.io/archie-next/`, path prefix `/archie-next/`. Push to `main` → rsync over SSH to Reclaim Hosting (cPanel shared host). PDF generation is a separate manual workflow (`pdf.yml`).

**The production target is entirely driven by GitHub repository variables** (`DEPLOY_HOST`/`DEPLOY_USER`/`DEPLOY_PORT`/`DEPLOY_PATH`/`SITE_URL`/`ALLOW_CRAWLERS`/`MAX_DELETIONS`/`SSH_KNOWN_HOSTS`), never hardcoded in the YAML — the pre-cutover preview subdomain and the live docroot differ by three variable edits and no code change. See README.md's Deployment section for the full table, the dry-run recipe, the cutover procedure, and rollback. The `deploy-production` job is self-contained: it builds *and* runs the checks itself rather than depending on the `build` job, so the bytes that get checked are the bytes that ship. `check-anchors` and `check-contrast` block the deploy; `check-links` stays advisory, since external link rot in an old article must not block publishing a new issue. A preflight step asserts the build is complete and correctly configured before rsync runs with `--delete`.

Server-owned paths (`.htaccess`, `.well-known/`, `cgi-bin/`) are on the rsync exclude list, so they're never overwritten and never deleted — `--delete-excluded` must never be added, since it would invert that list into a kill list and break AutoSSL renewal.

`site.url` comes from `SITE_URL` (default: the canonical `https://archipelagosjournal.org`), and `src/_data/site.js` throws if it isn't https, or if `ELEVENTY_ALLOW_CRAWLERS=true` is combined with a non-canonical `SITE_URL` — so a mistyped variable can't ship preview canonicals or a preview sitemap to a crawlable build.

`robots.txt` is generated (`src/robots.11ty.js`), not static — it defaults to blocking all crawlers and only allows them, with a sitemap reference, when `ELEVENTY_ALLOW_CRAWLERS=true`. The same env var drives `site.noindex` and a `<meta name="robots" content="noindex, nofollow">` in `head.njk`. **Both are required, and the meta tag is the one that matters for staging:** robots.txt is only honored at a *host root*, so the copy served at `elotroalex.github.io/archie-next/robots.txt` is ignored entirely. Any subpath deploy depends on the meta tag alone.

**Staging path prefix vs. hardcoded content paths.** The `staging` branch's GitHub Pages preview is served under `/archie-next/` (`ELEVENTY_PATH_PREFIX` in `build.yml`), which Eleventy's `url` filter applies automatically to every template-generated link (nav, css/js, page-to-page links). Article markdown, however, hardcodes root-absolute image paths (e.g. `src="/issue09/images/foo.jpg"`) and is never routed through Nunjucks (`markdownTemplateEngine: false`), so those paths never pick up the prefix and 404 on staging even though they resolve fine on production (no prefix). Rather than touch the frozen URL/content conventions, `utility/fix-staging-paths.js` runs as a CI-only postprocess step in `build.yml` (staging job only, after the Eleventy build) that rewrites root-absolute `src=`/`href=` attributes in the built `_site` HTML to add the prefix — skipping anything already prefixed, so it's idempotent and safe to run alongside template-generated links. It's a no-op without a prefix, so local dev (`npm run build`/`npm run serve`) and the production rsync deploy are never affected.
